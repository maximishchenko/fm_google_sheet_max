# manager_tasks

Python-скрипт, который забирает задачи менеджеров на сегодня из Google-таблиц и отправляет их в мессенджер MAX через бота.

Рассчитан на запуск по расписанию: уже отправленные задачи запоминаются, повторно не отправляются. Если новых задач на сегодня нет — сообщение не отправляется.

## Как это работает

1. Для каждой таблицы из `config.json` скачивает лист в формате CSV (прямой экспорт Google Sheets, без API-ключей).
2. Находит строки, у которых дедлайн приходится на сегодняшнюю дату (в таблице это состояние «Сегодня»).
3. Отбрасывает задачи, которые уже были отправлены сегодня (история хранится в `sent_tasks.json`).
4. Печатает полный список в консоль и отправляет новые задачи каждому получателю из `chat_ids`.

Ключ задачи составной (`№ заявки + объект + этап`), поэтому строки с одинаковым номером заявки, но разными изделиями считаются разными задачами. История отправленных сбрасывается каждый день.

## Требования

- Python 3.7+ (только стандартная библиотека, зависимостей нет).
- Google-таблицы с доступом «Все, у кого есть ссылка» → «Читатель».
- Бот в MAX: токен берётся в разделе **Чат-боты → Настройки**.

## Установка и настройка

1. Склонируйте репозиторий.
2. Создайте `config.json` рядом со скриптом:

```json
{
    "max_bot_token": "токен бота MAX",
    "tables": [
        {
            "url": "https://docs.google.com/spreadsheets/d/<id>/edit?gid=<gid>",
            "chat_ids": ["213842560"]
        },
        {
            "url": "https://docs.google.com/spreadsheets/d/<id2>/edit?gid=<gid>",
            "chat_ids": ["111", "222"]
        }
    ]
}
```

- `tables` — список таблиц; каждая содержит задачи одного менеджера.
- `chat_ids` — кому отправлять задачи этой таблицы (несколько получателей — перечислите через запятую). Поддерживается и `user_id`.
- Токен можно задать переменной окружения `MAX_BOT_TOKEN` — она имеет приоритет над конфигом.

### Как узнать chat_id

1. Напишите боту любое сообщение в MAX.
2. Выполните:

```powershell
curl.exe -k -H "Authorization: <токен>" https://platform-api2.max.ru/updates
```

3. В ответе найдите `message.recipient.chat_id`.

## Запуск

```bash
python manager_tasks.py            # обработать все таблицы из config.json
python manager_tasks.py sheet.csv  # отладка: вывести задачи из локального CSV без отправки
```

### Запуск по расписанию (Windows, каждые 5 минут)

Планировщик заданий → создать задачу:

- Программа: `python`
- Аргументы: `C:\путь\к\manager_tasks.py`
- Триггер: по расписанию, повторять каждые 5 минут.

## Структура проекта

| Файл | Назначение |
|---|---|
| `manager_tasks.py` | основной скрипт |
| `config.json` | таблицы, получатели, токен бота (не коммитить — содержит секреты) |
| `sent_tasks.json` | история отправленных задач, создаётся автоматически |
| `AGENTS.md` | исходная постановка задачи |

## Особенности

- **Сертификаты Минцифры.** Домен API MAX (`platform-api2.max.ru`) использует TLS-сертификат НУЦ Минцифры. Скрипт сам скачивает корневой и промежуточный сертификаты с `gu-st.ru` при необходимости — ничего устанавливать в систему не нужно.
- **Лимит сообщения.** Тексты длиннее 4000 символов автоматически делятся на несколько сообщений.
- **Повреждённое состояние.** Если `sent_tasks.json` испорчен (например, после ручного редактирования с ошибкой в JSON), он переименовывается в `sent_tasks.json.broken`, а история начинается заново — об этом выводится предупреждение.

## Устранение неполадок

| Проблема | Решение |
|---|---|
| `HTTP Error 401/404` при загрузке таблицы | Откройте доступ к таблице по ссылке (Читатель) |
| `chat_id не найден` | Проверьте ID через `/updates`; скрипт пробует отправку и по `user_id` |
| Пришёл весь список вместо новых задач | Проверьте, что `sent_tasks.json` не удалён и валиден; чтобы переотправить всё — удалите файл |
| Пустой ответ `/updates` | Сначала напишите боту любое сообщение, затем повторите запрос |
